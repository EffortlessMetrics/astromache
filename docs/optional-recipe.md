# Optional search and offline recipe boundaries

`recipes/search-offline` is an independent private project with its own lockfile and three exact vendored candidates. `candidate-artifacts.json` records their hashes and source commits. Copy the directory independently and use its documented frozen installation and qualification commands. The complete `starters/publication` provides the same shared publication design without the optional search and offline packages.

AstroMache is the publication product; the unpublished `astromache@0.2.0` candidate provides eighteen exports covering publication layout, typography, article/list/taxonomy presentation, reading tools, document/navigation and gallery mechanics. Published `astromache@0.1.0` remains an immutable earlier package. Static search and offline mechanics are separate sibling packages, not additions to its component exports. Real sites consume packages directly and retain their own content, layout, corpus, privacy and deployment policies.

`@effortlessmetrics/astro-offline` uses locally bundled Workbox 7.4.1. It owns corpus digest checks, revision identity including actual bundled dependencies, atomic rejected installs, sequential acquisition, owned-cache cleanup and registration recovery. Consumer options define route lists/globs, hard budgets, fallback, migration ownership and connection policy. Optional `claimClients` only claims after activation; it does not bypass waiting, reload tabs or call skipWaiting. The personal integration preserves its existing first-install control; business and this recipe naturally acquire control later.

Generated workers include complete owner-code MIT and Google Workbox MIT notices; those bytes participate in revision identity. API routes are excluded and no contact queue is implemented. Public package exports are browser client and Node build integration; internal worker source is bundled by the integration rather than a consumer API.

The recipe demonstrates a two-note consumer-owned substring search engine, immutable corpus version, offline search-index retrieval, gallery and local fallback. It is not the personal content corpus, a MiniSearch worker engine, or a production deployment. Publication of any candidate requires separate authorization.

The recipe pins the reviewed unpublished static-search 0.1.0 candidate (source d9e59ea7c7c862512fc6d1ac398022461b0a0800; SHA-256 ccdcd96da60f4bb22c40fd14895b7c926e0a8165c2ebe34edfffd937dceff11c), including generation-local startup cleanup, fallback deadline/abort coverage and transport-timeout fallback isolation. Earlier 29f2f695, 1397a808 and dc249112 archives remain historical evidence. The current foundation pin is astromache 0.2.0 SHA-256 53bf0fa41d2371c5941fa1422ae83563002744bd684e45c7b048b548d2182874; the offline candidate remains c70bb2cf. Exact full identities are in candidate-artifacts.json. Search aborts the departing caller while preserving its backend for a persisted BFCache document; genuine document teardown disposes it. Qualification requires an actual persisted Back restoration with the same document marker and another successful offline query. The worker test harness uses bounded Node polling of awaited browser evaluations so asynchronous readiness cannot be mistaken for a truthy Promise.
