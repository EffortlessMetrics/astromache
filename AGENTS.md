# Working on the AstroMache starter

This repository owns the standalone public starter. Follow [README.md](README.md) for setup, [source ownership](README.md#source-ownership), focused tests and library upgrades. Shared components belong to astromache-core; offline and static-search remain separate specialist libraries. Keep private content and producer qualification infrastructure outside this starter, and retain scoped upstream notices.

Use the Node and pnpm versions declared in [package.json](package.json). Keep the working session and compatible dependency/build caches warm. Refresh installation, generated output or evidence when changed inputs or required checks warrant it. Preserve the offline integrity, cache revision and natural activation controls described in the README; cached output alone is not fresh acceptance.

Choose local checks and substantive challenge for the affected behavior using the existing README and package scripts. Complete required checks and approvals on their required candidate. The [starter workflow](.github/workflows/starter.yml) checks PR heads, main pushes and composed candidates on `merge_group: checks_requested`. This event support does not enable a merge queue or demonstrate hosted queue qualification. Keep desired lifecycle changes separate from deployed obligations.

When independent agent review is needed, use a subagent inside the working session, retaining the candidate and warm context. Do not assume optional `ub-review` capacity or transfer review to another executor by default. Preserve valid earlier reviews; refresh affected review or proof when changes or new findings warrant it. Additional passes should answer a concrete remaining question.

Bind evidence to its commit/tree, runtime, command, result and observation time. When carrying evidence forward, retain its original identity and explain why it still applies. The browser results in [STARTER-DELIVERY.json](STARTER-DELIVERY.json) and [CANONICAL-QUALIFICATION.json](CANONICAL-QUALIFICATION.json) are historical receipts that predate later product changes; they are not fresh HEAD acceptance. Preserve those receipts and distinguish local acceptance, hosted acceptance, registry release and deployment approval.

Keep one continuing writer for each candidate and coordinate shared-file ownership. Before reset or handoff, leave a recoverable checkpoint in the existing task or PR record: request source and time, later scope corrections and actual holds; repository/ref, exact commit/tree and dirty paths; completed, denied, pending or uncertain operation outcomes; evidence pointers and their original subjects; and the continuing owner and next unfinished action. Check uncertain outcomes before retrying. Preserve published history, retained archives and security controls; continue only within the assigned scope and authorization.
